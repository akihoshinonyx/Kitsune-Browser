# Разработка Kitsune Browser 1.6

Этот документ фиксирует состав выпущенного релиза 1.6.0.
Текущая опубликованная версия — 1.6.0.

## Этапы

1. Надёжность профиля: атомарная запись JSON, сохранение паролей между запусками,
   отказ от небезопасного сохранения новых паролей при недоступном шифровании ОС.
2. Изолированные приватные окна: временная сессия, отсутствие записи истории,
   паролей и списка вкладок, очистка после закрытия. Не заменять окна вкладками
   без явного изменения требований.
3. Данные и разрешения сайтов: очистка cookies/кэша/хранилищ, корректный отзыв
   временных и постоянных разрешений, проверки iframe и приватного режима.
4. Загрузки: пауза, продолжение, повтор, выбор пути и достоверные ошибки открытия.
5. Вкладки: звук, выгрузка неактивных вкладок, восстановление после сбоя.
6. Поведенческие Electron-тесты: локальный HTTP-сервер, IPC, переходы, popup,
   приватность, пароли, загрузки и внутренние страницы.

## Проверки перед выпуском

- Unit/regression tests, синтаксис и проверка diff.
- Smoke с отдельным временным профилем, без изменения пользовательского.
- Реальные Windows/Electron окна и собранные x64/ia32 установщики.
- Проверка зависимостей и сценариев обновления существующего профиля.

## Текущее состояние первого этапа

- Реализована запись JSON через временный файл, fsync и rename без предварительного
  удаления основной копии. При ошибке замены прежний файл остаётся доступен.
- Исправлена коллизия PasswordStore.save(entry) и Store.save(): сохранение,
  обновление, удаление и flush паролей теперь действительно записывают файл.
- Добавлены проверки повторного открытия хранилища, ошибки rename и сериализации.
- Smoke использует новый временный userData/sessionData вместо основного профиля.
- Новые пароли теперь сохраняются только через `safeStorage`; старые `raw:`-записи
  не раскрываются без шифрования и автоматически мигрируют на защищённый формат,
  когда шифрование ОС становится доступно.

Для приватных окон сначала требуется убрать зависимость IPC и сервисов от
глобальных mainWindow/tabs: запрос должен попадать в контекст окна отправителя.

## Текущее состояние второго этапа

- Добавлен отдельный контекст приватного окна с непостоянной Chromium-сессией
  (`kitsune-private-*`) и собственным `TabManager`.
- Запросы вкладок, состояния, поиска, отступов и управления окном маршрутизируются
  по `event.sender`; приватное окно не использует основной `tabs`.
- В приватном контексте не записываются история и стек закрытых вкладок, не
  выполняется восстановление вкладок, а каналы истории, паролей, закладок и
  постоянных загрузок не отдают данные.
- При закрытии приватного окна его вкладки уничтожаются, после чего временная
  сессия очищается через `clearStorageData()`.
- Сетевой adblock, User-Agent и обработчики разрешений подключаются к каждой
  сессии; приватная сессия не сохраняет постоянные permission grants.
- Smoke-тест проверяет два окна, раздельное состояние вкладок, запрет истории,
  паролей и настроек, а также закрытие приватного окна без закрытия основного.
- Локальный HTTP smoke-сценарий записывает cookie, localStorage, sessionStorage
  и Cache Storage в приватном окне, затем открывает новое окно и проверяет, что
  данные не восстановились.

Этап изолированных приватных окон закрыт и вошёл в релиз 1.6.0. Следующий этап:
дополнительные данные и разрешения сайтов.
Одна лишь смена partition вкладки не обеспечивает приватность.

## Ограничения дополнительных функций

Полная совместимость с Chrome Web Store не следует из поддержки отдельных
extension API Electron. Поддержка расширений требует отдельной оценки API,
модели разрешений, установки и обновлений.

Облачная синхронизация требует выбора сервера, аутентификации, модели
сквозного шифрования, разрешения конфликтов и процедуры восстановления ключа.
Не публиковать заглушки этих функций как готовую поддержку.
