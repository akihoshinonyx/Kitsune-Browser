# Kitsune Browser — описание проекта

**Kitsune Browser** — настольный браузер для Windows на движке Electron/Chromium
с настоящей сетевой блокировкой рекламы (совместимой с правилами Adblock Plus и
uBlock Origin), менеджером паролей и приватным поиском DuckDuckGo по умолчанию.
Без телеметрии, без облачных сервисов, без аккаунтов.

* Текущая версия: **1.0.0**
* Репозиторий: <https://github.com/akihoshinonyx/Kitsune-Browser>
* Релизы (установщики): <https://github.com/akihoshinonyx/Kitsune-Browser/releases>
* Лицензия: MIT

## 1. Идея

Обычный Chromium «из коробки» ничего не блокирует: реклама и трекеры грузятся
вместе с сайтом, а единственный способ их убрать — ставить расширение и
доверять ему доступ ко всем страницам. Kitsune переносит блокировку внутрь
браузера:

| Что | Как решено |
|---|---|
| Реклама и трекеры | Сетевая блокировка через `session.webRequest` до того, как запрос уйдёт в сеть |
| Баннеры, которые рисует сам сайт | Косметические правила (`##`, `#@#`, `#?#`, `:has-text()`) вставляются в страницу через `insertCSS` |
| Рекламные скрипты, без которых сайт ломается | `$redirect` — вместо скрипта отдаётся пустышка |
| UTM-метки и «хвосты» ссылок | `$removeparam` — адрес переписывается без меток |
| Всплывающие окна | Popup открывается как вкладка, рекламные сети гасятся по `$popup` |
| Слежка за пользователем | Нет телеметрии, поиск DuckDuckGo, `DNT: 1`, свой User-Agent без метки Electron |

Блокировщик работает и в 32-битной, и в 64-битной сборке, правила кэшируются,
а статистика видна на внутренней странице `kitsune://blocked`.

## 2. Возможности

### Блокировка рекламы (уровень uBlock Origin)
* Синтаксис ABP/uBO: `||domain^`, `/regex/`, `*`, `^`, `@@`-исключения,
  опции `$script`, `$image`, `$third-party`, `$domain=`, `$important`,
  `$generichide`, `$popup`, `$redirect`, `$removeparam`, `$~тип`.
* Косметические правила: `##.banner`, `#@#`, `#?#div:has-text(Реклама)`,
  процедурные `:has-text()` выполняются скриптом на странице.
* **Пипетка элементов** — «заблокировать элемент» из меню или по правому клику:
  селектор подбирается автоматически и сохраняется как пользовательское правило.
* Свои правила (`||ads.example.com^`) — хранятся в `adblock-user.txt`.
* Белый список сайтов — блокировку можно выключить для одного домена.
* Загрузка больших списков: кнопка на `kitsune://blocked` скачивает
  EasyList + EasyPrivacy + Cookie (≈100 000 правил) в `userData/filters`.

### Приватность
* Поиск DuckDuckGo по умолчанию (обычный, Lite, HTML-версия без JavaScript).
* Три режима безопасного поиска: выключен / умеренный / строгий (`kp=-2/-1/1`).
* Никакой телеметрии и внешних аналитических сервисов.
* User-Agent собирается вручную: сообщается настоящая версия Chromium и метка
  `Kitsune/1.0.0`, без `Electron/…` — иначе сайты отдают упрощённые страницы.
* Заголовки `DNT: 1`, запрет нежелательных разрешений (уведомления, геолокация
  и медиа — по решению пользователя).

### Работа с браузером
* Вкладки: перетаскивание с подсветкой цели, дублирование, закрытие остальных
  и справа, восстановление сессии, счётчик блокировок на каждой вкладке.
* Недавно закрытые (25 адресов) и `Ctrl+Shift+T`.
* Закладки и история: локальные JSON-файлы, боковая панель, поиск, удаление.
* Поиск на странице (`Ctrl+F`) с подсветкой и счётчиком совпадений.
* Масштаб страницы с бейджем процентов, инструменты разработчика (F12).
* Горячие клавиши перехватываются в main-процессе через `before-input-event`,
  поэтому работают, даже когда фокус внутри страницы.
* Меню-«гамбургер» рисуется нативным `Menu.popup()`: HTML-меню оказалось бы под
  нативной вкладкой.

### Менеджер паролей
* Диалог «Сохранить пароль?» после отправки формы входа.
* Автозаполнение форм (в том числе на React/Vue-сайтах — через нативный setter
  и события `input`/`change`).
* Шифрование средствами ОС: DPAPI в Windows, Keychain в macOS, libsecret в Linux
  (`safeStorage`). Если шифрование недоступно, браузер честно об этом сообщает.
* Страница `kitsune://passwords`: список входов, показ пароля по требованию,
  удаление, очистка хранилища.

### Обновления
* Автообновление из GitHub Releases через `electron-updater`: проверка при
  запуске и раз в 6 часов, загрузка в фоне, установка по кнопке.
* Два независимых канала: 64-битная сборка берёт `latest.yml`, 32-битная —
  `win32.yml`. Иначе 32-битный браузер скачал бы 64-битный установщик.
* Проверить обновления можно из меню, со страницы `kitsune://settings` и из
  полосы уведомления внизу окна.
* Portable-сборка не обновляет себя: её заменяют вручную (браузер подскажет).

## 3. Архитектура

```
src/
├── main/                    main-процесс (Node.js, полный доступ)
│   ├── main.js              окно, сессия, IPC, меню, диагностика
│   ├── tabs.js              TabManager: WebContentsView на каждую вкладку
│   ├── adblock.js           движок правил ABP/uBO
│   ├── filters/             встроенный список + загрузка внешних
│   ├── store.js             JSON-хранилища (настройки, история, закладки, пароли)
│   ├── passwords.js         менеджер паролей (диалоги, автозаполнение)
│   ├── updater.js           автообновление из GitHub Releases
│   ├── ipc-guards.js        проверки отправителя IPC
│   └── url-utils.js         разбор адресов и внутренних схем
├── preload/preload.js       мост contextBridge (два уровня доступа)
├── renderer/                HTML/CSS/JS интерфейса (изолирован от Node)
│   ├── index.html           хром окна: вкладки, адресная строка, полоса обновления
│   └── pages/               внутренние страницы kitsune://
└── shared/                  константы и версия (main + renderer)
```

**Почему вкладки — это `WebContentsView`, а не `<webview>`.** `WebContentsView`
даёт отдельный процесс на вкладку, честный `webContents` и не ломает
`contextIsolation`. Обратная сторона: нативный слой рисуется **поверх** HTML,
поэтому всё, что интерфейс показывает ниже 88 px «хрома» (меню, подсказки,
боковая панель, полоса обновления), требует, чтобы main-процесс сдвинул
активную вкладку — это делает `TabManager.setInsets()`. Меню-«гамбургер» по той
же причине нативное.

**Поток запроса через блокировщик:**

```
страница → webRequest.onBeforeRequest → adblock.getAction()
                                        ├── block       → cancel: true
                                        ├── redirect    → redirectURL (пустышка)
                                        └── removeparam → новый URL без меток
                                          ↓
                                     recordBlocked() → статистика вкладки
                                          ↓
                                     IPC-событие adblock:count → счётчик в UI
```

Косметика применяется отдельно: `applyCosmetics()` собирает CSS-правила для
домена страницы и вставляет их через `webContents.insertCSS()`, а процедурные
правила (`:has-text()`) выполняются скриптом с `MutationObserver`.

## 4. Безопасность

| Механизм | Реализация |
|---|---|
| Изоляция контекста | `contextIsolation: true`, `nodeIntegration: false` |
| Два уровня API | `window.kitsune` — только внутренним страницам (`file://`); обычным сайтам доступен лишь `window.kitsunePage` (пароли и пипетка) |
| Проверка отправителя IPC | `ipc-guards.js`: приватные каналы (пароли, история, закладки, настройки, обновления) отвечают только внутренним страницам или «своему» домену |
| CSP | `default-src 'self'` на всех внутренних страницах |
| Пароли | `safeStorage` (DPAPI/Keychain/libsecret), в списке — только маски |
| Внешние ссылки | открываются через `shell.openExternal`, а не внутри окна |
| Обновления | HTTPS к GitHub, SHA-512 установщика из `latest.yml` проверяется до запуска |

## 5. Данные

Всё хранится локально, в `%APPDATA%\Kitsune Browser` (Electron `userData`):

| Файл | Содержимое |
|---|---|
| `settings.json` | настройки, включая белый список и последнюю сессию |
| `history.json` | история (до 5000 записей) |
| `bookmarks.json` | закладки |
| `passwords.json` | входы; пароли зашифрованы средствами ОС |
| `adblock-user.txt` | свои правила блокировки |
| `adblock-whitelist.json` | сайты, где блокировка выключена |
| `filters/*.txt` | скачанные списки (EasyList и другие) |

## 6. Технологии

| Компонент | Версия |
|---|---|

| Chromium | 152.x / 150.x |

| electron-builder | 25.x (упаковка и установщики) |
| electron-updater | 6.x (автообновление) |
| Установщики | NSIS + portable, две архитектуры |

Внешняя runtime-зависимость одна — `electron-updater` (и его транзитивные
пакеты); всё остальное написано внутри проекта.

## 7. Ограничения (честно)

* **Установщики не подписаны сертификатом.** Windows SmartScreen покажет
  предупреждение «Windows защитила ваш компьютер» — нужно нажать «Подробнее» →
  «Выполнить в любом случае». Для подписи нужен платный сертификат code signing;
  конфигурация сборки к нему уже готова (`win.certificateFile` /
  `win.certificatePassword`).
* **32-битная сборка использует Electron 43.** Начиная с Electron 44 проект
  больше не выпускает бинарники `win32-ia32`, поэтому 32-битная версия собрана
  на последней поддерживающей ветке. Функциональность идентична.
* **Portable-сборка не обновляется автоматически** — её файл заменяют вручную.
* Автообновление работает только для установленной (NSIS) сборки под Windows.
* Профиль браузера общий для 32- и 64-битной сборок
  (`%APPDATA%\Kitsune Browser`), поэтому переходить между ними можно без потери
  данных.
